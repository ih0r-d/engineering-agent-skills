# Consumer-facing documentation

- Lead with who the tool is for, the problem it solves, prerequisites, and the smallest working setup.
- Provide copyable commands and minimal code samples using verified names, versions and paths.
- Organize by user goals: install, first run, configure, troubleshoot, upgrade.
- Don't explain implementation internals unless a user must know them to use the API correctly.
- Avoid unsubstantiated performance claims, obsolete feature lists, repeated setup steps or excessive configuration matrices.
- Link to advanced technical material instead of overloading the quick start.
