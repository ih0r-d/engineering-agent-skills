# Task Decomposition Checklist

| Concern | Check |
| --- | --- |
| Slice | One coherent outcome with a clear boundary. |
| Acceptance | Observable completion and relevant failure conditions. |
| Dependencies | Explicit prerequisites and integration points. |
| Risk | Isolate uncertainty into discovery work when necessary. |
| Coverage | Trace all items back to the approved objective. |

## Gotchas

- Separate frontend and backend tasks may hide an untested integration boundary.
- Do not treat uncertain estimates as commitments.
- Parallel work can still conflict on shared contracts or migrations.
- Avoid duplicating acceptance criteria without identifying the integration owner.
