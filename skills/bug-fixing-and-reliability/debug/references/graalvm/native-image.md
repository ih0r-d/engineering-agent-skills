# GraalVM Native Image compatibility

Load when a Java application is compiled to a native executable or fails only in native-image mode. Confirm the GraalVM distribution, release, build plugin, target platform, and whether the build uses the current reachability metadata format.

## Find the dynamic boundary

- Reproduce with the native executable and the relevant workload. JVM success does not establish native-image compatibility.
- Trace reflection, resource lookup, serialization, JNI, dynamic proxies, service loading, generated bytecode, and classpath scanning to their runtime inputs. Static analysis cannot infer arbitrary runtime-selected classes or resources.
- Prefer framework-supported native integration and library-provided metadata. Add the narrowest application metadata only for dynamic access the build cannot infer; broad registration increases image contents and can hide missing integration.
- Use the tracing agent against representative paths to collect candidate metadata, then review and test it. A trace only records behavior exercised during that run; it does not prove completeness for unvisited inputs or deployments.

## Initialization and verification

- Check build output for unresolved classes, resources, and initialization warnings. Decide build-time versus run-time class initialization from side effects and environment access; moving initialization to build time can embed build-machine state or trigger work too early.
- Exercise reflection, serialization, resource loading, locale/time-zone behavior, and error paths in the produced executable. Run on each supported target architecture and operating system where native behavior differs.
- Keep metadata adjacent to the owning artifact using the supported `META-INF/native-image` layout or framework conventions. Validate metadata against the toolchain version; schema and plugin behavior are version-sensitive.
- Compare startup, memory, and binary-size claims against the JVM deployment with equivalent workload and resource limits. Native compilation does not guarantee faster throughput.
