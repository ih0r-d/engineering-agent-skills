# Release readiness: <product and version>

This checklist records readiness evidence. It does not authorize publishing or deployment; obtain the required project approval separately.

## Scope and compatibility

- [ ] Release scope and supported target are identified.
- [ ] Version policy, compatibility impact, and breaking changes are reviewed.
- [ ] Required approvals and release owner are recorded.

## Build, tests, and dependencies

- [ ] Build provenance and source revision are known.
- [ ] Required test and quality gates passed; failures or omissions are explained.
- [ ] Dependency and security changes are assessed.

## Release materials and artifact

- [ ] Changelog and release notes accurately describe changes.
- [ ] Migrations and upgrade requirements are documented and compatible.
- [ ] Artifact identity, integrity, and provenance are verified.

## Deployment and recovery readiness

- [ ] Target environment and deployment prerequisites are understood.
- [ ] Rollback or roll-forward criteria and recovery owner are defined.
- [ ] Post-release verification signals and expected results are defined.
